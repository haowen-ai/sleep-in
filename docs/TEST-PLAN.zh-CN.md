# Sleep In v2 测试设计与开发闸门

[English](TEST-PLAN.md) · 简体中文

**状态：测试设计，尚不是测试通过报告。** 按用户要求，先设计场景、固定数据和预期，再继续功能开发。已经开始的功能草稿保留在开发分支，不以其当前行为反向定义产品正确性。测试环境只使用虚构数据和隔离工作目录。

目标：证明这是可以拖拽编排、跨语言传递数据、按计划执行复杂工作流的平台；同时证明用户可以自由选择输入，后台可在插电或电池供电时持续工作。不能用“按钮存在”“HTTP 202”“进程退出0”代替完成证据。

## 2. 先锁定数据语义

1. **连线与传参分开。** A→B表示执行依赖；B只接收自己配置的输入，不自动继承A的全部输出。画布位置和节点创建顺序不构成依赖。
2. **不使用上游输出是合法配置。** B可以只用常量、流程参数、其他可达节点的输出，或空输入对象 `{}`；没有必需输入声明时允许执行。
3. **不使用与缺失不是一回事。** 用户未绑定某字段，且该字段非必需，可以不存在；已声明必需绑定却取不到，必须报错，不能静默填null。
4. **空值不代表缺失。** `null`、`false`、`0`、空字符串和`[]`都必须原样传递。可选绑定仅在来源缺失/被跳过等明确情况下使用用户配置的默认值，不能用真假值判断替代。
5. **不传数据不等于忽略失败。** A→B仍要求A正常完成；若不需要此依赖，删除连线。需要容忍失败时使用明确的失败/可选依赖策略，与可选字段分别配置。
6. **SQL多行作为一次输入。** 三行结果传入Python时，Python默认运行一次，拿到完整三行；不能隐式逐行运行三次。
7. **路径相对`output.data`。** 绑定`rows`指向结构化输出的data.rows；stdout/stderr仅是日志，不进入输入。字段重名由稳定节点ID区分。
8. **跨语言用约定数据。** JSON对象/数组与制品引用，不传进程内DataFrame对象或另一个进程的绝对文件路径。高精度数和超出JS安全范围的整数用带schema的字符串。
9. **分支要有结束信号。正常条件未命中不是失败，不自动变成partial。** 不选中的分支为skipped，合并等待策略明确；没有被选中的路径不能导致永久等待。
10. **改草稿不改运行快照。** 受理后固定图、源码、环境、参数与映射；已受理运行不混入随后发布的新版本。

## 3. 固定测试数据

统一数据集 F-ORDERS（虚构）：

```json
[
  {"order_id":"A001","amount":"10.50","region":"华东"},
  {"order_id":"A002","amount":"20.25","region":null},
  {"order_id":"A003","amount":"0.00","region":"西部"}
]
```

SQL节点结构化数据为 `{rows: F-ORDERS, rowCount: 3, columns: ...}`。配置Python的 `orders ← SQL.rows`，Python精确计算并输出：

```json
{"schemaVersion":1,"data":{"summary":{"count":3,"total":"30.75"}},"artifacts":[]}
```

JavaScript输入绑定 `summary ← Python.summary`，应得到count整数3、total字符串`"30.75"`，并生成包含相同值的结果文件。测试断言对象深度相等、类型、顺序、节点执行次数与制品内容，不能只断言run是success。

补充固定数据：空查询`[]`；单行；1001行（界面只预览前100行）；`null/false/0/""`；整数字符串`"9007199254740993"`；金额`"0.10"+"0.20"`必须得到`"0.30"`；中文与emoji；超过1MiB数据用完整制品引用。大数据测试在隔离临时目录生成，不引用真实业务文件。

## 4. 第一批必须完成的黄金路径

| 场景 | 配置/操作 | 精确预期 |
|---|---|---|
| SQL → Python → JS | 三行F-ORDERS，逐节点绑定 | 每节点一次；Python和JS都得到count3/total30.75；最终文件内容一致 |
| 不使用上游输出 | SQL→Python连线保留；Python输入只配置`label="weekly"` | Python在SQL完成后仅收到`{"label":"weekly"}`，无rows自动注入 |
| 完全不需要输入 | SQL→Python；Python无必需输入且inputs为空 | Python收到`{}`并运行一次；有依赖但不强制传数据 |
| 混合来源 | Python同时绑定SQL.rows、流程参数report_date、常量currency | 三类输入分别正确，不互相覆盖，不混入历史样例 |
| 可选缺失输出 | 绑定不存在字段 optional=true，default=[] | 仅该字段变成[]；必需绑定缺失的对照用例必须失败 |
| 上游空结果 | SQL查询0行→Python | 收到[]，count0；不是missing/failed，仍只执行一次 |
| 跨运行隔离 | 绕过受理策略的独立执行器测试使用同一冻结图的两个已受理run，A输入10/B输入20；产品受理另测默认重叠跳过 | 下游分别得到10和20；无共享临时文件覆盖、无输出串线 |
| 多源汇合 | 两个SQL源→Python，输入名orders/rates | 分别保留两个命名输入，等待策略正确；不能按行号自动拼表 |
| 真实自动触发 | 已发布图每分钟执行一次 | 到点自动创建run并经过真实n8n图；无需手动点运行 |
| 跨天重复 | 每天同一时间连续两天 | 首日完成不停止次日调度；真实试验与模拟时钟结果分别记录 |

“用户不使用上游输出”和“可选输出不存在”必须是两条独立用例；前者不发生读取，后者发生读取但按明确规则回退。

## 5. 测试层次与环境

- **单元测试**：纯图校验、映射、类型、时区、状态转换。固定时钟，预期时间直接写明，禁止用被测函数生成期望值。
- **组件/进程测试**：真正启动Python、Node、Shell、C、Java进程读写文件协议；工具链缺失独立记录，不能用mock当作语言支持证据。
- **API与数据库集成**：鉴权、事务、发布快照、受理去重；SQLite本地与PostgreSQL并发分别验证。
- **真实数据库集成**：PostgreSQL/MySQL/Oracle分别记录驱动、服务版本、只读/写入模式和结果。SQLite通过不等于其他方言通过。
- **真实n8n端到端**：保存→发布→定时受理→n8n节点调用→跨语言结果→下载。保留run/version/node/attempt与n8n关联证据。
- **浏览器交互**：实际拖动、连线、选输入、切语言、保存再打开、测试和查看结果。纯JS模型测试不代替浏览器验证。
- **真实Mac试验**：电池/插电、锁屏、关闭窗口、连续重复运行、重启、授权状态。模拟电源事件不等于实际电池测试。关机/合盖/电池耗尽不能承诺软件继续运行。

Mac硬件试验不得突然锁定用户正在使用的电脑、拔电、重启或改登录项。需要真实机器动作的用例保留为明确的人工步骤，使用专门测试窗口或经用户安排后执行。

## 6. 每次测试必须留什么证据

用例执行记录字段：case_id、构建提交、时间、OS/架构/运行环境版本、输入/fixture版本、预期、实际结果、状态、run_id/node_id/attempt、自动化命令或人工步骤、必要截图/日志的脱敏路径、失败原因与复现说明。

状态限定：`DESIGNED`（已设计）、`RED`（已证明目标功能尚未满足）、`PASS`、`FAIL`、`BLOCKED_ENV`、`NOT_RUN`。设计完成、测试函数存在、进程启动、HTTP202、exit0均不能自动记PASS。不要将含密码、令牌或真实数据的原始日志提交GitHub。

## 7. 开发执行顺序

1. 先审查用例的输入与预期是否互相矛盾，更新API/PRD语义；不能围绕已写代码删掉难测用例。
2. 第一批自动化：SQL→Python→JS、无上游输入、空结果、可选缺失与必需缺失、类型保持、时区预览、重复受理。先运行并记录RED，再实现。
3. 完成单链路后做多源汇合、分支skipped、失败/重试、取消/超时和副作用不确定性。
4. 再接画布交互与表单定时，跑真实n8n与真实浏览器。
5. 最后验证Mac安装/后台生命周期、可选工具链/数据库、迁移备份、权限和发布包；无法在当前环境验证的项目明确列为阻塞，不能扩大支持声明。

所有P0问题必须在对应能力交付前解决；签名、公证、真实Oracle或48小时Mac验证等外部条件要独立列出。测试矩阵是开发约束，不是已经达到这些能力的宣传材料。
